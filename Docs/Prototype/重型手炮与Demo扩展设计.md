# 零界重型手炮与 Demo 扩展设计

版本 V0.1；日期 2026-10-30。状态：新增设计提案，尚未实现；需策划评审。现有可运行 Windows 试玩包不含本武器。

## 目标

增加一把赛博朋克风格的高伤害重型手枪，以稀缺弹药提供危急时刻的爆发选择。拳套继续承担可持续的格挡、储能和反击。首版选用实体稀缺弹药，不同时制作冷却技能、能量充能和弹药三套机制。

外观以用户提到的《赛博朋克》厚重手枪和马洛里安 3516 的整体气质为参考，制作原创轮廓，不直接复制现有武器。用户提到的“边缘行者2king”具体武器身份尚未核对，不将其型号或设定编入本项目。

## 武器身份和世界观

暂名：HC-03「断响」；编号、名称和来源均为新增提案，不是原设定定稿。
定位：现代应急装备中的重型副武器，采用科幻特种弹药；工业外观增加赛博电子状态显示，与旧设施拳套形成两代装备对比。
这不是 CSM-017、牵引器或碰撞回声的新设定，也不默认弹药使用人体晶体。
既有方案主角在电梯事故中失枪。若未来接回完整剧情，本武器应在实验室的封闭装备柜里重新取得，不能无解释地出现在主角初始背包。

## 美术功能分区

| 外观分区 | 表达 | 游戏反馈 |
|---|---|---|
| 厚重枪口护套 | 短而宽的矩形前端，有强烈手炮质量感 | 短促枪口闪光与一次强反馈 |
| 散热外壳 | 石墨黑、枪灰金属及磨损边缘，少量散热槽 | 射击后短暂余光；不做独立过热系统 |
| 状态灯 | 窄幅青色指示条，少量琥珀警示 | 有弹与空弹可区分，不能只有颜色区别 |
| 简洁瞄具 | 保持第一人称目标可见 | 初版只用屏幕准星 |
| 握把与护圈 | 厚握把、清楚的手枪比例，非步枪轮廓 | 举枪、收枪占位动作 |
| 特种弹匣 | 与枪身连贯的短弹匣外观 | HUD 显示剩余弹数；首版不制作换弹动画 |

整体色彩：石墨黑、拉丝枪灰、克制的青色状态灯与琥珀提示。避免霓虹覆盖整把武器。表格只描述虚构游戏道具的外观与功能，不是现实制造图纸。
右手拳套与手枪如何共存仍待美术确定：首版用切换装备表现，不允许一边举枪一边用同一只手格挡。右手前臂装置可保留，拳端机构是否妨碍握枪需要建模前确认。

## 首轮试玩参数

| 参数 | 提案值 | 原因 |
|---|---|---|
| 获得武器时弹药 | 2 发 | 能演示威力，也能感受到资源有限 |
| 弹药上限 | 3 发 | 避免囤弹后全程替代拳套 |
| 每次射击消耗 | 1 发 | 按一次左键射击一次，不自动连发 |
| 单发伤害 | 4 点 | 高于现有普通拳 1 点和储能拳 2 点 |
| 射击间隔 | 0.9 秒 | 明显节奏，避免连点覆盖敌人所有动作 |
| 有效距离 | 15 米 | 适配小实验室；用射线并受墙体阻挡 |
| 非致命命中击退初速度 | 8 米/秒 | 先复用现有碰撞击退机制，需实机调参 |
| 命中恢复窗口 | 1.2 秒 | 命中打断敌人攻击，明确窗口，待测试 |
| 切换装备时间 | 0.35 秒 | 防止切换瞬间同时射击与格挡 |
| 可拾取额外弹药 | 初版 0，选做一处 +1 发 | 先避免新增探索路线 |

全部数值为设计起点，当前脚本未包含这些字段。当前普通敌人 3 血会被手炮一击击败；用于对比的第二个敌人可临时设为 6 血，4 点手炮加 2 点储能拳可击败。6 血只作为测试配置，不代表新增敌人种类或既定护甲机制。
拳套储能不能转换成枪械弹药；不使用击杀自动回弹，不使用冷却自动恢复弹药。

## 输入与状态

1 键切拳套，2 键切手炮。左键执行当前武器的攻击。只有拳套模式能右键格挡；手炮模式暂不提供瞄准镜、蓄力和其他右键技能。
开谜题 UI、死亡、结算及切换途中不能射击或格挡。空弹点击只显示反馈，不消耗拳套储能。点击恢复鼠标控制不能同时射击。松开右键不能自动开枪。
初版将剩余弹数作为唯一可用弹药池，不额外加入备弹、弹匣换弹、卡壳、配件、穿墙、跳弹和武器升级。弹匣外观不意味着已经实现换弹。

## 接入小 Demo 的推荐流程

这是基于策划“解谜加战斗”方向的工作提案，不冒充已确认关卡脚本。

1. 进入实验室，操作终端完成简化校准。
2. 校准成功只解锁拳套支架；实际拾取拳套后才启动第一名 3 血敌人。
3. 第一阶段展示现有格挡储能反击；手炮此时尚不可拿，避免开场直接跳过拳套体验。
4. 第一名被击败后解除手炮柜锁定。玩家可拾取带 2 发弹药的手炮，出现第二名同模型 6 血敌人。
5. 第二阶段允许使用手炮爆发，也允许继续用拳套通过；打空不能导致无法完成。
6. 第二名被击败后解锁出口。玩家走到出口触发完整 Demo 胜利，R 或按钮重试恢复全流程。

拾取手炮和第二名敌人出现只触发一次。首次击败不能提前弹出现有 DemoRoundManager 的最终胜利画面；需要由新流程管理器推进阶段。两名敌人顺序出现，不在原单敌人结算脚本外简单复制一个敌人。
如果明天时间不足，最小接入版可先省略第二轮的正式入场演出，用可见门口的占位敌人激活实现。当前已验证的 Player3CTest 与试玩 ZIP 保留，新增流程在复制场景开发。

## 程序接入顺序

先完成共用 E 键交互和 UI 输入切换，再接校准、拾取和阶段流程，最后增加手炮。
武器部分分为当前装备状态、拳套行为与手炮行为，避免让两个组件各自无条件处理左键。第一步只做射线命中、弹药计数、冷却、命中反馈和非致命击退。
复用 DemoEnemyHealth 扣血和 DemoEnemyKnockback 的墙体碰撞位移；保留拳套现有参数，不为体现手炮威力而降低拳套有效性。
重试重载保存场景，必须恢复玩家血量、零储能、武器未拾取、初始弹药、校准未完成、敌人初态和门锁状态。

## 验收

- 校准、拾取和入场分别成立，重复交互不重复获得武器或弹药。
- 取得手炮前，第一阶段能体验拳套；第一名被击败不会提前完成整个关卡。
- 手炮每次射击只扣一发；切换、开 UI、恢复鼠标或按住鼠标不会额外射击。
- 对比普通拳、储能拳和手炮，伤害与击退反馈可分辨；墙能阻挡射线和击退。
- 枪械模式不能同时拳套格挡；切回拳套仍保留原储能。
- 子弹用尽仍能通过拳套完成；额外弹药不能无限重复拾取。
- 第二阶段完成才开出口，主动走出后胜利；失败和胜利重试恢复全部状态。
- 在独立 Windows 构建再次验证，不以编辑器结果代替。
