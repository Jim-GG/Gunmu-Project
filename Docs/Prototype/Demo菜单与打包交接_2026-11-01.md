# 零界 Demo 菜单、重试与打包交接

日期：2026-11-01

## 本版可交付流程

开始菜单 → 终端校准与拾取拳套 → 三名教学敌人 → 第一关解谜 → 右侧门 → 第二关解谜 → 沟壑填平 → 后方门 → 通关菜单。

## 玩家界面

全部为中文占位 UI，可在打包版直接使用。

- 开始菜单：开始游戏、退出游戏。
- 死亡界面：重新挑战本房间、返回主菜单、退出游戏。
- 第二关结束界面：重新游玩、返回主菜单、退出游戏。
- Esc 暂停界面：继续游戏、重置当前房间、返回主菜单、退出游戏。
- R：正常游玩时重置当前房间；死亡界面重试当前房间；通关界面从头重玩。
- 终端面板打开时，Esc 优先关闭终端，不抢先打开暂停菜单。

开始界面出现时玩法暂停，鼠标可点击；点击开始后下一帧才恢复控制，避免菜单点击同时触发攻击。暂停、死亡、通关界面会隐藏玩法 HUD。退出游戏在 Unity 编辑器里会停止 Play，在 Windows 打包版里会关闭程序。

## R 与死亡重试的规则

R 采用重新加载当前场景的方式重置，人物回到该场景中保存的初始位置与朝向，同时恢复生命、初始装备、充能、敌人、门、平台、箱子、晶体和机关状态。

教学场景重试后需要重新校准终端、拾取拳套。第一关或第二关重试后，保留“进入该关就拥有拳套”的原规则，充能从该关初始值重新开始。

按住 R 不会反复重载新房间，必须松开后重新按下。低于场景初始高度 15 米默认视为坠落死亡，可在玩家 Room Restart Controller 组件中调整。

死亡后“重新挑战本房间”重试当前场景。通关后“重新游玩”从 Demo_IntroCombat 重新开始整个 Demo，不残留上一轮的生命、装备和机关状态。

## 脚本与替换入口

- Assets/Scripts/DemoSession.cs：跨场景菜单、暂停、死亡和通关流程。
- Assets/Scripts/Player/RoomRestartController.cs：R 重试与跌落判定，已装到本版三个场景的 Player。
- Assets/Resources/DemoUI/DemoSession.prefab：游戏名称、起始场景、界面颜色、“显示占位界面”开关。运行时自动创建，位于 DontDestroyOnLoad；编辑场景无需手动重复拖入。

后续替换 Canvas 或 UI Toolkit 时，保留 DemoSession 的流程，关闭“显示占位界面”，让正式界面按钮绑定以下公开方法：

StartGame、ResumeGame、RestartRoom、ReplayDemo、ReturnToMenu、QuitGame。

DemoSession.Mode 表示当前处于开始、游玩、暂停、死亡、通关或载入状态。正式 UI 应按状态显示，避免仅关闭占位界面后没有可操作按钮。

## 打包配置

已设置构建场景顺序，仅启用以下三个场景：

0. Assets/Scenes/Demo_IntroCombat.unity
1. Assets/Scenes/Level1_Billiards.unity
2. Assets/Scenes/Level2_Pendulum.unity

SampleScene 与第三至第五关仍保留在列表中，但本版不勾选。打包版中不启用数字键直接跳开发关卡。

Unity 内操作：

1. 停止运行并保存场景。
2. File → Build Profiles → Windows，确认 Scene List 与上述一致。
3. 点击 Build，选择新的空输出目录，例如 Builds/ZeroBoundaryDemo_v02。
4. 打开生成的 exe，从开始菜单体验到第二关通关菜单，再试一次重新游玩和退出。
5. 分发时压缩整个输出文件夹，包含 exe、数据目录及同目录 DLL 等文件；不要只发送 exe。

本轮未自动重新打包，也未提交、推送 Git。原有打包文件不会自动包含本轮改动，需重新 Build。

安装器菜单：Tools → 零界 → 配置 Demo 菜单与打包入口。
本轮安装前的场景与构建配置备份位于 Library/DemoReleaseBackups/；Library 不会上传 Git。
